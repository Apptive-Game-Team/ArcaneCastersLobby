# 모델 준비 상태에 따른 매칭 제외

모델 봇을 활성화할 때 로비의 `LEARNED_BOT_CONFIG`에도 게임 서버와 동일한 `game-config.json`을 읽기 전용으로 연결합니다. 로비는 `assignments`의 음수 봇 ID와 버전을 읽습니다. 파일이 지정됐는데 없거나 잘못된 형식이면 시작을 실패시킵니다. 파일을 지정하지 않으면 모델 봇을 구분하지 않으므로 모델 봇 배포 시 이 설정을 반드시 함께 적용해야 합니다.

로비는 기존 서비스 인증으로 게임 서버의 `GET /api/server/learned-bots`를 조회합니다. 응답은 `{ "-123": "candidate-v9-001" }` 형태입니다. 모델 파일이나 프로세스가 없거나, 응답 버전이 다르거나, 게임 서버가 API를 지원하지 않으면 해당 모델 봇은 제외합니다. 모델 봇 ID가 없는 세션을 서버에 배치할 때는 이 조회를 생략합니다.

연습 상대를 고를 때 사용할 수 없는 모델 ID를 SQL의 MMR 정렬과 후보 개수 제한 전에 제외합니다. 가용 서버 중 적어도 하나가 준비됐어야 후보가 됩니다. 실제 세션 배치에서도 대상 서버의 준비 상태를 다시 확인하므로 지정 봇 매칭과 다른 서버로의 재시도에도 같은 조건이 적용됩니다. 조회 제한은 `learned-bots.timeout`이며 기본 2초입니다. 성공 상태를 캐시하지 않습니다.

모델 프로세스를 내리는 동안에도 assignments 파일을 유지하세요. 파일을 제거하면 해당 ID를 일반 봇으로 해석하게 됩니다. 완전히 일반 봇으로 되돌릴 때만 로비와 게임 서버 양쪽에서 assignments를 제거합니다. DB 변경이나 클라이언트 변경은 필요하지 않습니다.

## 서버별 배치와 로컬 경기

온라인 경기는 해당 모델을 사용할 수 있는 게임 서버에만 배치합니다. 핑이 더 낮아도 모델이 없는 서버는 건너뜁니다. 두 모델 봇의 경기라면 같은 게임 서버가 두 모델을 모두 사용할 수 있어야 합니다. 서로 다른 서버에 각각 준비됐다는 이유만으로 경기를 생성하지 않습니다.

`POST /api/local-sessions`의 연습 경기는 `selectLocal` 경로를 사용합니다. 로컬에는 모델 프로세스를 띄우지 않으므로 원격 서버의 준비 여부를 조회하지 않고 assignments에 등록된 모든 모델 봇을 후보에서 제외합니다. 접대봇과 접대봇 부재 시 MMR 기반 대체 상대에도 이 조건을 적용합니다. 온라인 연습·대기열 봇 매칭은 기존 서버별 준비 확인 경로를 유지합니다.
